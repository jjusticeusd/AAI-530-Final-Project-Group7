## Introduction

In this final project, your team will design and build an applied large language model (LLM) project that addresses a real-world communication, analysis, productivity, learning, or decision-support need. Example projects include an educational assistant, content-generation tool, document summarizer, knowledge assistant, workflow support tool, evaluation assistant, or another approved LLM-based application.

The goal of the project is to demonstrate that your team can move beyond simple prompting and design an applied LLM workflow with a clear purpose, defined users, customized instructions, appropriate context handling, and responsible evaluation. Your project does not need to be production-ready, but it should be functional enough to demonstrate how an LLM can be integrated into a practical use case.

This project is a Level 4 on the AIAS Scale because it requires intentional and documented use of AI tools in the design and development process. Your team should use LLMs or other AI tools to support ideation, planning, coding, debugging, prompt development, testing, documentation, and revision. However, your team remains responsible for understanding, modifying, evaluating, and explaining all project components. The final submission should demonstrate both effective AI-assisted development and thoughtful human judgment.

When your team completes this project, you should have a portfolio-quality example of your ability to design, build, test, document, and responsibly evaluate an LLM-enabled application or workflow.

## Project Requirements

Your team’s final project must include the following elements:

  1. **Applied LLM Use Case****  
**The project must address a specific user need, professional context, educational purpose, communication task, analysis problem, or workflow. The project should have a clear audience and a defined purpose.
  2. **LLM Integration****  
**The project must integrate an LLM through an API, hosted model, approved development platform, or open model. Your team should clearly document which model or service was used and how it supports the intended task.
  3. **Prompt or Instruction Customization****  
**The project must include customized prompting, system instructions, prompt templates, role instructions, examples, structured outputs, or another method for shaping model behavior. Your team should explain how the instructions were developed, tested, and revised.
  4. **Context, Evaluation, or Safety Feature****  
**The project must include at least one additional design feature beyond basic prompting. Examples include context handling using uploaded documents, retrieved text, structured inputs, or user-provided background; an evaluation process comparing outputs across prompts, models, examples, or test cases; or safety and responsible-use features such as content boundaries, refusal conditions, human review, disclosure language, source-checking, or output verification.
  5. **Testing and Evaluation****  
**The project must include a small set of test cases or scenarios used to evaluate whether the LLM application performs as intended. The evaluation should address accuracy, usefulness, consistency, limitations, risks, and fit for the intended audience or use case.
  6. **Documentation, AI Use, and Ethical Reflection****  
**The final submission must document the project’s purpose, design, implementation, testing, limitations, responsible-use considerations, and use of AI during development. Your team should reflect on how AI tools shaped the project workflow and on potential issues such as privacy, bias, hallucination, misuse, transparency, accessibility, intellectual property, and the need for human oversight.



## Project Deliverables and Submission Format

Each team will submit the following final project package.

### 1\. GitHub Repository

Each team must submit the URL to a GitHub repository containing the most recent and cleaned version of the project. The repository must be shared with the instructor or made publicly accessible if the team intends to use it as a portfolio item.

The repository should include, as appropriate to the project:

  * source code, notebooks, scripts, configuration files, or exported workflow files;
  * prompt files, system instructions, templates, examples, or other materials used to customize the LLM;
  * sample inputs, selected outputs, screenshots, or demonstration materials;
  * testing or evaluation materials;
  * documentation needed to understand and run or review the project; and
  * a README file.



The README file should clearly describe the project purpose, repository structure, setup or usage instructions, required tools or services, model or API used, major files, known limitations, and any steps needed for the instructor to review or run the project.

If the project uses a no-code or low-code platform, the repository should still include exported files, screenshots, prompt documentation, workflow diagrams, configuration notes, testing materials, and any other artifacts needed to evaluate the project. If API keys, credentials, or private data are used, they must not be included in the repository. The README should instead explain what credentials or environment variables would be required.

### 2\. Project Documentation

Submit a written project document that explains:

  * project title, purpose, and intended users;
  * real-world problem or use case addressed;
  * LLM model, API, platform, or open model used;
  * prompt, instruction, or customization strategy;
  * context-handling, evaluation, or safety feature included;
  * project workflow or system design;
  * test cases or evaluation scenarios;
  * results of testing and revisions made;
  * known limitations and failure modes;
  * ethical and responsible-use considerations;
  * how AI tools were used during development; and
  * recommendations for future improvement.



The documentation should be clear enough that another informed reader could understand what the team built, why the team built it, how it works, how AI was used in development, and how well the project performed.

### 3\. Prompt and Testing Appendix

Submit an appendix, table, or separate file that includes the major prompts, system instructions, test cases, evaluation criteria, and selected outputs used in the project. This section should show how the project was tested and revised.

Your team does not need to include every experimental prompt, but the appendix should provide enough evidence to demonstrate meaningful iteration, testing, and evaluation.

### 4\. AI Use and Ethical Reflection

Submit a brief reflection explaining both how AI was used to support project development and what ethical, social, and practical considerations are associated with the completed project.

The AI use portion should identify the AI tools used by the team, describe how they supported the work, and explain how the team verified, modified, or rejected AI-generated suggestions. The reflection should make clear that the team understands and takes responsibility for the final project.

The ethical reflection should address the risks most relevant to the use case, such as hallucinated information, overreliance on AI, privacy, sensitive data, bias, accessibility, transparency, copyright or intellectual property, misuse, and human oversight.

This reflection may be included in the main documentation or submitted as a separate section.

### 5\. Final Presentation and Demonstration

Submit a recorded presentation and demonstration, typically 10–15 minutes total.

The first portion of the presentation should be a concise introduction of **no more than five minutes**. This section should explain the problem, intended users, project design, LLM integration, customization strategy, evaluation approach, key limitations, and responsible-use considerations.

The remaining portion of the presentation should be a demonstration of **at least five minutes**. The demonstration should show the project in action through a working frontend, hosted application, notebook, command-line interface, API call, no-code workflow, or other approved format. If the project does not have a frontend, a code walk-through with visible inputs, outputs, and explanation of the workflow is acceptable. The demonstration should focus on how the application works and what it produces rather than simply describing the project at a high level.

The presentation should make clear:

  * what the user or stakeholder would experience;
  * how the LLM is integrated;
  * how prompts or instructions shape the output;
  * what context, evaluation, or safety features are included;
  * what happens in at least one representative test case or scenario;
  * what limitations or failure modes remain; and
  * how the project could be improved in future development.
